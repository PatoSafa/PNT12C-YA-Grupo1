Conectar un Frontend con un Backend Spring Boot

Guía paso a paso para alumnos: desde una página HTML hasta una API REST y una base de datos MySQL.

Objetivo de esta guía
Al finalizar, vas a poder crear una página HTML que se comunique con una API REST desarrollada con Spring Boot. El ejemplo continúa el proyecto de alumnos utilizado en la guía de Spring Boot.

¿Qué significa "conectar Frontend con Backend"?

El Frontend es la parte de la aplicación con la que interactúa el usuario. El Backend contiene la lógica de negocio y expone servicios que pueden ser utilizados por el Frontend.

👤 Usuario
→
🌐 Frontend
HTML + JavaScript
→
🌱 Backend
Spring Boot
→
🗄️ MySQL

La comunicación entre Frontend y Backend se realiza mediante HTTP. El Frontend envía una solicitud a una URL de la API y Spring Boot devuelve una respuesta, normalmente en formato JSON.

1Antes de empezar: nuestro Backend

En la guía anterior construimos una API REST para administrar alumnos. La estructura incluye un modelo Alumno, un repositorio y un controlador. 

alumnos-api/
└── src/
    └── main/
        └── java/
            └── com/example/alumnosapi/
                ├── AlumnosApiApplication.java
                ├── controller/
                │   └── AlumnoController.java
                ├── model/
                │   └── Alumno.java
                └── repository/
                    └── AlumnoRepository.java
Importante: el Frontend no se conecta directamente a MySQL. El acceso a la base de datos lo realiza el Backend. El Frontend se comunica con Spring Boot.

2Crear un endpoint REST

Para que el Frontend pueda consultar alumnos, Spring Boot debe exponer un endpoint. Un ejemplo sencillo es un método GET que devuelve todos los alumnos. 

@RestController
@RequestMapping("/api/alumnos")
public class AlumnoController {

    private final AlumnoRepository repository;

    public AlumnoController(AlumnoRepository repository) {
        this.repository = repository;
    }

    @GetMapping
    public List<Alumno> obtenerAlumnos() {
        return repository.findAll();
    }
}

En este caso, la URL del endpoint será: 

GET http://localhost:8080/api/alumnos

Si el backend encuentra, por ejemplo, dos alumnos, podría devolver: 

[
    {
        "id": 1,
        "nombre": "Ana",
        "email": "ana@email.com"
    },
    {
        "id": 2,
        "nombre": "Juan",
        "email": "juan@email.com"
    }
]
Idea clave: el Controller es el punto de entrada de las solicitudes HTTP que recibe nuestra API.

4Utilizar fetch() para llamar al Backend

JavaScript proporciona fetch() para realizar solicitudes HTTP. Vamos a utilizarlo para consultar el endpoint de Spring Boot. 

async function cargarAlumnos() {

    const respuesta =
        await fetch("http://localhost:8080/api/alumnos");

    const alumnos =
        await respuesta.json();

    console.log(alumnos);
}

El proceso es:

→

→
GET /api/alumnos
→
Spring Boot

Luego Spring Boot procesa la solicitud, consulta el repositorio y devuelve los datos.

→

→

5Mostrar los datos en la pantalla

Recibir los datos no alcanza: debemos tomar el JSON y modificar el HTML para mostrarlo. 

async function cargarAlumnos() {

    const respuesta =
        await fetch("http://localhost:8080/api/alumnos");

    const alumnos =
        await respuesta.json();

    const lista =
        document.getElementById("listaAlumnos");

    lista.innerHTML = "";

    alumnos.forEach(alumno => {

        const item =
            document.createElement("li");

        item.textContent =
            alumno.nombre + " - " + alumno.email;

        lista.appendChild(item);
    });
}

Ahora, cuando el usuario presione "Cargar alumnos", el Frontend solicitará los datos al Backend y los mostrará.

6¿Qué es CORS?

Es posible que al abrir el HTML desde un origen y ejecutar Spring Boot desde otro, el navegador bloquee la solicitud por una política de seguridad llamada Same-Origin Policy.

Por ejemplo: 

Frontend:
http://localhost:5500

Backend:
http://localhost:8080

Aunque ambos están en nuestra computadora, utilizan puertos diferentes y, para el navegador, son orígenes diferentes.

¿Qué es CORS?
CORS (Cross-Origin Resource Sharing) es un mecanismo que permite indicar qué orígenes están autorizados a realizar solicitudes al Backend.

7Habilitar CORS en Spring Boot

Para una práctica sencilla podemos permitir el origen desde el que se ejecuta nuestro Frontend. Una alternativa es utilizar @CrossOrigin sobre el Controller. 

@RestController
@RequestMapping("/api/alumnos")
@CrossOrigin(origins = "http://localhost:5500")
public class AlumnoController {

    // ...

}

La dirección exacta depende de cómo ejecutes el Frontend. Si utilizás otra herramienta o puerto, debés colocar ese origen.

Para producción: no conviene habilitar cualquier origen sin analizar las necesidades de seguridad. En un proyecto real se configura CORS de acuerdo con los dominios autorizados.

8Enviar información: POST

Hasta ahora utilizamos GET para consultar información. Para crear un alumno podemos utilizar una solicitud POST.

En el Frontend podemos tener un formulario:

<form onsubmit="crearAlumno(event)">

    <input
        id="nombre"
        placeholder="Nombre"
        required>

    <input
        id="email"
        placeholder="Email"
        required>

    <button type="submit">
        Crear alumno
    </button>

</form>

JavaScript puede construir un objeto y enviarlo como JSON: 

async function crearAlumno(event) {

    event.preventDefault();

    const alumno = {
        nombre:
            document.getElementById("nombre").value,

        email:
            document.getElementById("email").value
    };

    const respuesta = await fetch(
        "http://localhost:8080/api/alumnos",
        {
            method: "POST",

            headers: {
                "Content-Type": "application/json"
            },

            body: JSON.stringify(alumno)
        }
    );

    if (respuesta.ok) {
        alert("Alumno creado correctamente");
    }
}

9El Backend recibe el POST

El Controller de Spring Boot debe tener un método que reciba el objeto enviado por el Frontend. 

@PostMapping
public Alumno crearAlumno(@RequestBody Alumno alumno) {

    return repository.save(alumno);
}

El flujo completo de creación es:

Formulario HTML
→
JavaScript
→
POST JSON
→
Controller
→
Repository
→
MySQL

Después, el Backend puede devolver el alumno creado como respuesta.

10DELETE: eliminar un alumno

También podemos enviar solicitudes para eliminar información. Por ejemplo: 

DELETE http://localhost:8080/api/alumnos/5

En Spring Boot:

@DeleteMapping("/{id}")
public void eliminarAlumno(@PathVariable Long id) {

    repository.deleteById(id);
}

Y desde JavaScript:

async function eliminarAlumno(id) {

    await fetch(
        "http://localhost:8080/api/alumnos/" + id,
        {
            method: "DELETE"
        }
    );

    cargarAlumnos();
}

11Los principales métodos HTTP

Método Uso habitual Ejemplo
GET Consultar información /api/alumnos
POST Crear información /api/alumnos
PUT Actualizar información /api/alumnos/5
DELETE Eliminar información /api/alumnos/5
Recordá: la URL identifica el recurso y el método HTTP expresa qué operación queremos realizar sobre ese recurso.

13Ejemplo final: Frontend completo

Este ejemplo reúne la consulta y la creación de alumnos en una sola página. 

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Gestión de Alumnos</title>
</head>

<body>

    <h1>Gestión de alumnos</h1>

    <form onsubmit="crearAlumno(event)">

        <input
            id="nombre"
            placeholder="Nombre"
            required>

        <input
            id="email"
            type="email"
            placeholder="Email"
            required>

        <button type="submit">
            Crear
        </button>

    </form>

    <hr>

    <button onclick="cargarAlumnos()">
        Actualizar listado
    </button>

    <ul id="listaAlumnos"></ul>

    <script>

        const API =
            "http://localhost:8080/api/alumnos";

        async function cargarAlumnos() {

            const respuesta =
                await fetch(API);

            const alumnos =
                await respuesta.json();

            const lista =
                document.getElementById(
                    "listaAlumnos"
                );

            lista.innerHTML = "";

            alumnos.forEach(alumno => {

                const item =
                    document.createElement("li");

                item.textContent =
                    alumno.nombre +
                    " - " +
                    alumno.email;

                lista.appendChild(item);
            });
        }

        async function crearAlumno(event) {

            event.preventDefault();

            const alumno = {
                nombre:
                    document.getElementById(
                        "nombre"
                    ).value,

                email:
                    document.getElementById(
                        "email"
                    ).value
            };

            const respuesta =
                await fetch(API, {

                    method: "POST",

                    headers: {
                        "Content-Type":
                            "application/json"
                    },

                    body:
                        JSON.stringify(alumno)
                });

            if (respuesta.ok) {

                alert(
                    "Alumno creado correctamente"
                );

                event.target.reset();

                cargarAlumnos();
            }
        }

    </script>

</body>
</html>

14¿Cómo ejecutar todo?

Backend

Desde el proyecto Spring Boot:

.\gradlew.bat bootRun

Spring Boot quedará escuchando en: 

http://localhost:8080

Base de datos

Según la guía anterior, MySQL se ejecuta mediante Docker Compose: 

docker compose up -d

Frontend

El archivo index.html debe ejecutarse desde un servidor web local para evitar problemas con el origen de la aplicación. Una alternativa sencilla durante la práctica es utilizar un servidor local desde el editor de código.

Checklist:
  • ☑ MySQL está ejecutándose.
  • ☑ Spring Boot está ejecutándose.
  • ☑ El endpoint GET funciona.
  • ☑ El Frontend está ejecutándose.
  • ☑ CORS permite el origen del Frontend.
  • ☑ fetch() puede comunicarse con Spring Boot.
  • ☑ Los alumnos aparecen en pantalla.

La idea fundamental:
El Frontend no accede directamente a la base de datos. El Frontend se comunica con la API de Spring Boot mediante HTTP. Spring Boot procesa la solicitud y utiliza el Repository para acceder a MySQL. Luego devuelve una respuesta al Frontend.
