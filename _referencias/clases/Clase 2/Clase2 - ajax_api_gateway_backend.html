AJAX, API Gateway y Backend

¿Cómo se comunica una página web con un servidor?

1. El problema

Cuando trabajamos con una aplicación web, muchas veces necesitamos enviar información desde el navegador hacia un servidor.

Por ejemplo, cuando un usuario completa un formulario y presiona "Guardar", el navegador necesita enviar esos datos al backend.

Una forma habitual de realizar esta comunicación desde JavaScript es mediante una llamada HTTP utilizando AJAX.

2. ¿Qué significa AJAX?

AJAX significa Asynchronous JavaScript and XML.

El concepto de AJAX permite que JavaScript realice una petición al servidor sin necesidad de recargar toda la página.

Importante: actualmente no necesariamente utilizamos XML. Es muy común trabajar con JSON.

En aplicaciones modernas, las llamadas AJAX suelen realizarse mediante la función fetch() de JavaScript.

Lógica del sistema

El flujo básico es:

  1. El usuario realiza una acción.
  2. JavaScript obtiene los datos.
  3. JavaScript realiza una petición HTTP.
  4. La petición llega al API Gateway.
  5. El API Gateway determina a qué servicio/backend enviarla.
  6. El backend procesa la solicitud.
  7. El backend devuelve una respuesta.
  8. JavaScript recibe la respuesta y actualiza la página.

4. ¿Qué es un API Gateway?

Un API Gateway funciona como un punto de entrada para las solicitudes que llegan a diferentes APIs o servicios del backend.

Por ejemplo, imaginemos que tenemos estos endpoints: 

GET  /api/usuarios
POST /api/usuarios
GET  /api/productos
POST /api/productos
GET  /api/pedidos

El frontend no necesariamente necesita conocer cómo están organizados internamente todos los servicios. Puede comunicarse con el Gateway, que luego dirige cada solicitud al servicio correspondiente.

5. Una llamada AJAX con fetch()

Supongamos que nuestro backend expone el siguiente endpoint: 

GET http://localhost:8080/api/usuarios

Desde JavaScript podemos realizar una petición: 

fetch("http://localhost:8080/api/usuarios")
    .then(response => response.json())
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.error(error);
    });

En este ejemplo:

  • fetch() realiza la petición HTTP.
  • response.json() convierte la respuesta a un objeto JavaScript.
  • data contiene los datos recibidos.
  • catch() permite manejar errores.

6. ¿Y si queremos enviar información?

Supongamos que queremos crear un usuario.

Nuestro backend tiene: 

POST /api/usuarios

Podemos enviar un objeto JSON: 

const usuario = {
    nombre: "Ana",
    email: "ana@email.com"
};

fetch("/api/usuarios", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify(usuario)
})
.then(response => response.json())
.then(data => {
    console.log(data);
});

Acá aparecen algunos conceptos nuevos:

  • method: indica el método HTTP.
  • headers: informa características de la petición.
  • Content-Type: indica que estamos enviando JSON.
  • body: contiene la información enviada.
  • JSON.stringify(): transforma el objeto JavaScript en texto JSON.

7. Ejemplo completo: formulario + AJAX

El siguiente ejemplo toma un nombre desde un formulario y realiza una petición al backend. 

const formulario = document.getElementById("formUsuario");

formulario.addEventListener("submit", function(event) {

    event.preventDefault();

    const nombre = document.getElementById("nombre").value;

    fetch("/api/usuarios", {
        method: "POST",
        headers: {
            "Content-Type": "application/json"
        },
        body: JSON.stringify({
            nombre: nombre
        })
    })
    .then(response => response.json())
    .then(data => {
        document.getElementById("resultado").innerText =
            "Usuario agregado correctamente";
    })
    .catch(error => {
        document.getElementById("resultado").innerText =
            "Ocurrió un error";
    });

});

8. ¿Dónde interviene cada tecnología?

Tecnología Responsabilidad
HTML Define la estructura y los elementos de la página.
CSS Define la apariencia visual.
JavaScript Permite agregar comportamiento e interacción.
AJAX / fetch() Permite realizar peticiones HTTP desde el navegador sin recargar toda la página.
API Gateway Recibe solicitudes y las dirige hacia los servicios/API correspondientes.
Backend Procesa la solicitud, ejecuta la lógica y devuelve una respuesta.

9. Actividad para los alumnos

Actividad 1: Modificá el formulario para solicitar nombre y email.
Actividad 2: Modificá el objeto JSON enviado al backend para incluir ambos datos.
Actividad 3: Cambiá el endpoint para representar un recurso diferente. Por ejemplo: /api/productos.
Actividad 4: Mostrá en la página los datos recibidos en la respuesta. No utilices solamente console.log().
Actividad 5: Agregá un mensaje diferente para una respuesta exitosa y para un error.
Actividad 6: Identificá qué parte de la aplicación corresponde al frontend, cuál al API Gateway y cuál al backend.
