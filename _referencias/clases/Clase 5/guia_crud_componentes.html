CRUD de Componentes

En esta guía vamos a completar la pantalla Home para que podamos consultar, crear, modificar y eliminar componentes utilizando nuestra API REST.

La comunicación entre el HTML y el backend se realiza mediante JavaScript y fetch().

1. ¿Qué vamos a agregar?

En la pantalla Home tendremos:

  • Una tabla con los componentes.
  • Un botón + para agregar un componente.
  • Un botón ✏️ para editar.
  • Un botón 🗑️ para eliminar.
  • Un formulario para crear y modificar componentes.

Los campos de un componente son:

Campo Descripción
id Identificador del componente.
descripcion Descripción del componente.
color Color del componente.
medida Medida del componente.

2. Paso 1: obtener los componentes con GET

Objetivo: consultar al backend y mostrar en la tabla los componentes que existen.

El endpoint es:

GET /api/componente

Desde JavaScript hacemos una petición:

fetch("/api/componente")
    .then(response => response.json())
    .then(componentes => {
        // mostrar los componentes
    });

El backend devuelve una lista de componentes, por ejemplo: 

[
    {
        "id": 1,
        "descripcion": "Componente 1",
        "color": "rojo",
        "medida": "estandar"
    },
    {
        "id": 2,
        "descripcion": "Componente 3",
        "color": "rojo",
        "medida": "estandar"
    }
]

JavaScript recorre esa lista y crea una fila de la tabla para cada componente.

3. Paso 2: agregar el botón +

El botón + permite comenzar la carga de un nuevo componente. 

<button onclick="nuevoComponente()">+</button>

Al hacer clic se ejecuta nuevoComponente(), que prepara el formulario vacío.

4. Paso 3: crear un componente con POST

Objetivo: enviar al backend los datos ingresados en el formulario.

Utilizamos:

POST /api/componente

Los datos se envían como JSON:

{
    "descripcion": "Componente nuevo",
    "color": "azul",
    "medida": "estandar"
}

La petición desde JavaScript es:

fetch("/api/componente", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify(datos)
});

JSON.stringify() convierte el objeto JavaScript en una cadena JSON para enviarla al backend.

5. Paso 4: editar un componente con PUT

Cada fila tiene un botón de edición. Al presionarlo, los datos del componente se cargan en el formulario.

Para guardar los cambios utilizamos:

PUT /api/componente

En este caso enviamos también el id:

{
    "id": 1,
    "descripcion": "Componente modificado",
    "color": "verde",
    "medida": "estandar"
}

La petición es:

fetch("/api/componente", {
    method: "PUT",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify(datosEdicion)
});
¿Por qué necesitamos el id? Porque el backend debe saber qué componente queremos modificar.

6. Paso 5: eliminar un componente con DELETE

El botón 🗑️ permite eliminar un componente. Para hacerlo necesitamos enviar su id.

La URL queda de esta forma:

DELETE /api/componente?id=3

Desde JavaScript:

fetch("/api/componente?id=" + id, {
    method: "DELETE"
});

Antes de realizar la eliminación se utiliza una confirmación para evitar borrar accidentalmente un registro.

7. Ajuste del Controller para DELETE

Como el id llega como parámetro de la URL, lo indicamos explícitamente con @RequestParam. 

@DeleteMapping
public ResponseEntity<String> borraComponente(@RequestParam Long id) {
    boolean eliminado = service.borrar(id);

    if (eliminado) {
        return ResponseEntity.accepted().build();
    } else {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body("Componente no encontrado");
    }
}
Atención: el mensaje de error corresponde a un componente, por eso debe decir "Componente no encontrado".

8. Paso 6: volver a cargar la tabla

Después de crear, modificar o eliminar un componente, volvemos a ejecutar: 

cargarComponentes();

De esta forma se vuelve a consultar el backend y la tabla queda actualizada con los datos actuales.

9. Resumen de los endpoints

Operación Método HTTP Endpoint
Consultar GET /api/componente
Crear POST /api/componente
Modificar PUT /api/componente
Eliminar DELETE /api/componente?id=...

10. ¿Qué sucede cuando usamos cada botón?

  1. + → abre el formulario vacío.
  2. Guardar un nuevo componente → realiza un POST.
  3. ✏️ → carga los datos existentes en el formulario.
  4. Guardar una modificación → realiza un PUT.
  5. 🗑️ → solicita confirmación y realiza un DELETE.
  6. Después de cada operación → se vuelve a ejecutar el GET para actualizar la tabla.

11. ¿Qué estamos aprendiendo?

  • Cómo conectar HTML y JavaScript con un backend.
  • Cómo utilizar fetch().
  • Cómo enviar y recibir JSON.
  • Cómo utilizar los métodos HTTP GET, POST, PUT y DELETE.
  • Cómo consumir una API REST desde el navegador.
  • Cómo actualizar una tabla dinámicamente.
  • Cómo implementar las operaciones básicas de un CRUD.

12. Flujo completo

Frontend → Backend → Base de datos

El usuario realiza una acción en el HTML. JavaScript envía una petición HTTP al Controller. El Controller utiliza el Service para realizar la operación correspondiente y luego devuelve una respuesta al navegador.

El flujo que implementamos es: 

HTML
  ↓
JavaScript + fetch()
  ↓
Controller
  ↓
Service
  ↓
Base de datos
  ↓
Respuesta al navegador
  ↓
Actualización de la tabla
Objetivo final: desde una única pantalla podemos consultar los componentes, agregar nuevos registros, modificar los existentes y eliminarlos, utilizando nuestra API REST.
