Idea principal: la vista no se conecta directamente a MySQL. La vista se comunica con el Backend mediante HTTP. El Backend se comunica con MySQL.

2Configuración de Docker

El archivo docker-compose.yml debe contener la configuración de MySQL.

services:
  mysql:
    image: mysql:8.4
    container_name: mysql-clase
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: clase
      MYSQL_USER: alumno
      MYSQL_PASSWORD: alumno
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:

¿Qué significa 3306:3306?

La primera parte corresponde al puerto de la computadora (host) y la segunda al puerto dentro del contenedor.

"3306:3306"
   │     │
   │     └── Puerto de MySQL dentro del contenedor
   └──────── Puerto disponible desde Windows
Para este proyecto: Windows → localhost:3306 → Docker → MySQL.

Levantar MySQL

docker compose up -d

Comprobar el contenedor

docker ps

Debe aparecer mysql-clase ejecutándose.

3Configuración del Backend

El Backend debe utilizar los mismos datos definidos en Docker. Por ejemplo, en application.yaml:

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/clase
    username: alumno
    password: alumno

  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true

Error frecuente: si Docker está configurado con 3306:3306, pero en el Backend se coloca otro puerto, la aplicación no podrá conectarse a MySQL.

4Configurar Git Bash

4.1 Abrir Git Bash

  1. Instalar Git for Windows.
  2. Abrir la carpeta donde está el proyecto.
  3. Hacer clic derecho dentro de la carpeta y seleccionar Open Git Bash here, si aparece esa opción.

4.2 Comprobar Git

git --version

4.3 Configurar nombre y correo

Utilicen el nombre y correo asociados a su cuenta de GitHub:

git config --global user.name "Tu Nombre"
git config --global user.email "tu-correo@example.com"

4.4 Verificar la configuración

git config --global --list

5Clonar el repositorio desde GitHub

Si el repositorio ya existe en GitHub y todavía no lo tienen en la computadora:

git clone URL_DEL_REPOSITORIO

Luego entrar a la carpeta:

cd nombre-del-proyecto

Comprobar que Git reconoce el proyecto:

git status
Si aparece información de la rama y del estado del repositorio, están trabajando dentro de un repositorio Git.

6Subir cambios a GitHub

Después de modificar el código:

6.1 Ver qué cambió

git status

6.2 Agregar los archivos

git add .

6.3 Crear el commit

git commit -m "Actualización del proyecto"

6.4 Subir a GitHub

git push
Secuencia para recordar:
git status
git add .
git commit -m "mensaje"
git push
No confundir: git add . prepara los cambios; git commit los guarda en el historial local; git push los envía a GitHub.

7Conectar la Vista con el Backend

La vista (HTML + JavaScript) debe comunicarse con los endpoints de la API del Backend.

Importante: la Vista → Backend → Base de datos. No hacemos Vista → Base de datos directamente.

7.1 El Backend debe estar ejecutándose

Por ejemplo, si Spring Boot está levantado en el puerto 8080, la API estará disponible en:

http://localhost:8080

Si tenemos un controlador con un endpoint:

@GetMapping("/elementos")
public List<Elemento> listar() {
    return repository.findAll();
}

La URL de la API será:

http://localhost:8080/elementos

7.2 Llamar al Backend desde JavaScript

Ejemplo utilizando fetch:

fetch("http://localhost:8080/elementos")
  .then(response => response.json())
  .then(data => {
      console.log(data);
  })
  .catch(error => {
      console.error("Error:", error);
  });

7.3 Mostrar los datos en la Vista

<ul id="lista"></ul>

<script>
fetch("http://localhost:8080/elementos")
  .then(response => response.json())
  .then(data => {

      const lista = document.getElementById("lista");

      data.forEach(elemento => {
          const li = document.createElement("li");
          li.textContent = elemento.nombre;
          lista.appendChild(li);
      });

  })
  .catch(error => {
      console.error("No se pudo conectar con el Backend:", error);
  });
</script>

Orden recomendado

  1. Levantar Docker y comprobar MySQL con docker ps.
  2. Iniciar el Backend desde IntelliJ.
  3. Comprobar que el Backend conecta correctamente con MySQL.
  4. Probar los endpoints con Postman.
  5. Abrir la Vista.
  6. Desde JavaScript, llamar al endpoint mediante fetch().
  7. Verificar los datos en el navegador.
Si todo funciona: la Vista realiza una petición HTTP → Spring Boot recibe la petición → el Backend consulta MySQL → obtiene los datos → devuelve JSON → JavaScript recibe el JSON → la Vista muestra la información.

9Errores frecuentes

ProblemaQué revisar
Backend no conecta con MySQLHost, puerto 3306, usuario, contraseña y nombre de la base.
Docker no muestra MySQLEjecutar docker ps y revisar docker compose up -d.
Connection refusedVerificar que MySQL esté levantado y que el puerto sea correcto.
La Vista no obtiene datosVerificar que Spring Boot esté ejecutándose y que la URL del endpoint sea correcta.
Error CORSRevisar la configuración de CORS del Backend cuando la Vista y API se sirven desde orígenes diferentes.
git push fallaVerificar que estén dentro del repositorio, la rama correcta y la autenticación con GitHub.
